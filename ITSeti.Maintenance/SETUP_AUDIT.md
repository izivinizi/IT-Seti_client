# ITSETI-Setup: проверка интеграции

Источник проверен на подключённом носителе: `F:\Service\ITSETI-Setup`. Это
облегчённый набор AnyDesk, RMS Host, OCS Inventory и Desktop Info с панелью.
Набора `system\packages\apps` для нового ПК нет.

## Реализовано

- Вкладка ПО показывает четыре компонента, их состояние и наличие пакетов.
- У каждого компонента есть отдельная команда установки; «Установить всё»
  выполняет четыре проверенных обработчика приложения по очереди.
- Установка передаётся задаче SYSTEM. Запрос содержит только путь набора и
  фиксированный ключ компонента из allowlist; пути к EXE или команды от клиента
  не принимаются.
- Хеш `Install.ps1` закреплён. Подписанные пакеты проходят только при совпадении
  текущего SHA-256 с проверенным комплектом. Для RMS MSI с `HashMismatch` и
  неподписанного OCS требуется то же точное совпадение SHA-256.
- Хеши `DesktopInfo.ini`, `update-support-ids.ps1` и `start-panel.vbs` закреплены:
  эти файлы копируются в общий `ProgramData` и попадают в автозапуск.
- Из приложения удалён режим приёмки. Передача `-Accept` и запуск ветки `-Apps`
  запрещены; локальные учётные записи и права этой интеграцией не меняются.

## Граница доверия

Исходный `Install.ps1` на носителе содержит дополнительные режимы, включая
приёмку и установку приложений нового ПК. Приложение не исполняет этот скрипт:
его хеш служит идентификатором проверенного комплекта, а установка выполняется
только встроенными обработчиками четырёх разрешённых компонентов. Скрипт и набор
организационных пакетов не копируются в публичный GitHub-релиз; там размещается
приложение обслуживания.

Обновление фиксированных пакетов требует ревизии нового комплекта и изменения
закреплённых хешей в приложении и `Install-OrganizationSoftware.ps1`. Простого
переименования файла недостаточно.
