# История объединённой заявки 24879

## Подтверждённая причина

Рабочая БД прочитана без изменений. В истории 14 сообщений. У импортированных сообщений время приёма в нашу БД одинаковое (16 октября 16:17:10 UTC), а исходные даты Okdesk лежат в диапазоне 14–16 октября и сохранены корректно. Admin conversation API выбирал и сортировал время приёма, игнорируя okdesk_created_at. Поэтому сообщения перемешивались по случайному UUID.

Комментарий об объединении с 24821 содержит HTML span/i/b/br. UI безопасно показывал этот HTML как буквальный текст.

## Исправление

- Admin и клиентская история используют исходное время Okdesk; резерв — локальная дата. При одинаковом времени порядок стабилен по remote comment ID, затем локальным данным.
- HTML входящих комментариев преобразуется в обычный текст при выдаче API: сохраняются переносы, пункты списков, ссылка-номер исходной заявки и дата, удаляются теги и исполняемые узлы. UI продолжает использовать textContent.
- Сырые remote content и даты в БД не переписываются. Пересинхронизация и миграция для 24879 не нужны; старые сообщения исправляются при следующем открытии истории.
- Сообщения пользователя остаются обычным текстом. UI различает пользователя, комментарий из Okdesk и локальный ответ инженера, не помечая импортированный ответ как отправленный сайтом.
- API-транспорт Okdesk теперь также сохраняет created_at, а не теряет исходную дату.

## Проверки

Release build: 0 предупреждений/ошибок. Полный server suite и Node frontend/navigation. Сценарии текста объединённой заявки, entity decoding, списков, опасного HTML, локального буквального текста и смещения временной зоны.

Реальные локальные HTTP admin/public API с намеренно перепутанными датами импорта: исходный порядок и дата, читаемый merge, пользовательский текст, приватность и сохранность raw content — PASS. Рабочая БД не менялась.
