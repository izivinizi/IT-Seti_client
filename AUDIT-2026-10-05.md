# Beta audit: 2026-10-05

## Implemented and tested

- Server policy: bounded persisted allowlist; malformed policy does not prevent startup.
- Windows 10/11: authenticated server software catalog, fixed SYSTEM installation worker, bounded downloads, exact size and SHA-256 validation, fixed silent-install recipes. Automatic updates skip missing software; Install All skips Yandex and WinRAR. Unknown installers are not executed.
- Timed-out installers are recorded for administrator review rather than blindly restarted.
- Server package upload: cleanup after failed uploads, transactional publication and per-package locking.
- Win7: bounded process-policy download, embedded-signature trust checks, default offline allowlist, maintenance results included before report upload.
- Win7 full schedule: daily eligibility check with a 60-day baseline, no immediate full check after registration and no daytime scheduler catch-up. Failed full checks remain eligible for retry.
- Main software UI: server packages enable installation without an embedded bundle; unknown package rows no longer break refresh through duplicate empty keys.
- Docker source build context now includes the shared diagnostic rules project and default policies, instead of referring to files outside the build context. A Dockerfile-specific allowlist excludes secrets and generated output.

## Verification

- Main solution and Win7 WPF port: Release builds, no warnings/errors.
- Server rules/policy console tests and browser script/theme tests passed.
- Diagnostic, cancellation, GitHub update and scheduled-policy contracts passed.
- Installer/bootstrap, assignment, organization setup, cleanup/task and disk-worker contracts passed.
- Win7 WPF smoke suite passed on the current Windows host, including cancellation, task error classification and 60-day gating.
- Software worker fixture exercised download, SHA-256 rejection and simulated installation; it changed no installed software.

## Not yet established / remaining work

- No execution on a real Windows 7 OS in this audit. Disk utilities, SMART mapping and cleanup under SYSTEM require testing on the user's Win7 PC.
- No real vendor installation/update was performed by the new worker; its installation test uses a process mock.
- PostgreSQL upload concurrency, Okdesk API round trips and a 3,000-device load test remain unverified.
- A source Docker build has not been exercised locally: Docker is not installed on this workstation. Production uses a locally compiled publication and its existing runtime image.
- Scheduled full cleanup must be audited further for active-user profile cleanup when no interactive cleanup bridge is running. Do not claim identical cleanup in every execution context yet.
- Main scheduled reports need verification after the final repair/cleanup stage, not merely after diagnostics.
- Win7 signature filtering does not yet implement full Windows catalog-signature parity.
- Follow-up fixed immediate catalog retrieval after enrollment and added a separate SYSTEM catalog task for startup/manual refresh. Fixture tests pass; a live SYSTEM refresh on the installed new build is still a pilot check.
- Existing installation payload directories and optional standalone Tools/Software payload need a safe upgrade migration; new main app publication excludes the organization bundle.

These are beta builds, not proof that all historical requirements are complete. Stable release manifests are intentionally unchanged.

## UI/catalog follow-up

- Shared secondary style and icon layout for Support, My Tickets and Contacts; WPF render inspected.
- Connected-PC setup retains enrollment without requesting the installation password again; isolated process test passes.
- Company and site search now use the editable dropdown itself. Runtime WinForms tests cover typing, address search, correct IDs and invalidating previous selections.
- Shared connection script reads JSON through .NET rather than PowerShell 3-only commands, for Win7 compatibility.
- Catalog refresh does not install software, does not expose the device key and retains cached packages if offline. Tests validate camel-case server JSON, platform priority and damaged/oversized files.
